# `structo::hw::vt100_terminal`

`include/structo/hw/vt100.hpp`

An xterm-flavoured VT100/ANSI escape-sequence interpreter built entirely on top of
[`console_ref`](console_ref.md), turning a byte stream into console
operations -- usable with any bound backend
([`vga_text_console`](vga_text_console.md),
[`framebuffer_console<PixelFormat>`](framebuffer_console.md), or a test
fake) since it only ever talks to the `console_ref` abstraction. It is
not limited to pure VT100: the commonly used xterm extensions are
supported so shells and full-screen tools work, and further ones can be
added to the same state machine.

```cpp
structo::hw::console_ref console(backend); // any adapted backend
structo::hw::vt100_terminal term(console);

term.feed("\x1b[2J\x1b[H");             // clear screen, home cursor
term.feed("\x1b[1;32mHello, green!\x1b[0m\r\n");
```

## Scope

Text cells with 16 colours; no scrollback, mouse generation or Unicode.

- **Character sets:** `ESC ( 0` / `ESC ) 0` select DEC special graphics for
  G0/G1 (`ESC ( B` / `ESC ) B` back to ASCII), `SO`/`SI` shift between
  them. Line drawing (mc, dialog, ncurses) is drawn as ASCII `-`, `|`, `+`.
- **Alternate screen** (`?47`/`?1047`/`?1049`): works when storage is
  supplied via `set_alternate_screen_storage`; otherwise only reported.

- **Cursor movement:** `CUU`/`CUD`/`CUF`/`CUB` (`A`/`B`/`C`/`D`),
  `CNL`/`CPL` (`E`/`F`), `CHA` (`G`), `VPA` (`d`), `CUP`/`HVP`
  (`H`/`f`, 1-based, default `1;1`), save/restore (`ESC 7`/`ESC 8`,
  `CSI s`/`CSI u`, including colours).
- **Erasing and editing:** `ED` (`J`), `EL` (`K`), `ECH` (`X`), `ICH`
  (`@`), `DCH` (`P`), `IL` (`L`), `DL` (`M`).
- **Scrolling:** `IND`/`NEL`/`RI` (`ESC D`/`E`/`M`), `SU`/`SD`
  (`CSI S`/`T`), and a scroll region (`DECSTBM`, `CSI top ; bottom r`).
- **Deferred autowrap (xenl):** writing in the last column leaves the
  cursor there with a pending wrap, so a full-width line followed by
  `\r\n` does not leave a blank row. `CSI ? 7 l`/`h` toggles autowrap.
- **`SGR`** (`m`): 16 colours (`30-37`, `40-47`, `90-97`, `100-107`),
  `1`/`22` (bold = bright foreground), `7`/`27` (reverse video),
  `39`/`49`, `0`, and `38;5;n` / `38;2;r;g;b` (and `48;...`) which are
  mapped to the nearest of the 16 colours. Underline, italic etc. are
  ignored.
- **Modes:** `CSI ? 25 h/l` shows/hides the cursor, `ESC c` (RIS) resets
  the terminal. Other private modes are consumed and reported through
  callbacks.
- **`OSC`** strings (`ESC ] ... BEL` or `... ESC \`) are consumed and
  delivered to callbacks; they never reach the screen.
- **Control characters:** `\r`, `\n`/`\v`/`\f` (**strict line feed**,
  see below), `\b`, `\t`, BEL (callback). NUL (terminfo padding), DEL
  and bytes >= 0x80 are ignored.
- Any other/unrecognized sequence (CSI with private markers, intermediate
  bytes, charset selects, ...) is fully consumed per ECMA-48's structure
  and silently ignored, rather than leaking onto the screen.

An omitted or explicit-`0` numeric parameter is treated as the
command's default (ECMA-48 convention), e.g. `ESC [ A` and `ESC [ 0 A`
both move the cursor up exactly one row.

## Events (`vt100_callbacks`)

Things that are not drawing but that the host may want to react to are
reported through optional function pointers, all null by default:

```cpp
structo::hw::vt100_callbacks cb;
cb.ctx = &my_window; // passed back as the first argument of every hook

// BEL: flash the window or beep.
cb.bell = [](void *ctx) noexcept { static_cast<window *>(ctx)->flash(); };

// OSC 0 / OSC 2: the program set the window title (truncated to 255 bytes).
cb.title = [](void *ctx, reloco::string_view text) noexcept { static_cast<window *>(ctx)->set_title(text); };

// Any other OSC (code 7 = current directory, 8 = hyperlink, 52 = clipboard, ...).
cb.osc = [](void *ctx, std::uint32_t code, reloco::string_view payload) noexcept { /* ... */ };

// DEC private modes: application cursor keys (1), bracketed paste (2004), mouse
// reporting (1000/1002/1003/1006), focus events (1004), alternate screen (47/1047/1049),
// application keypad (ESC = / ESC >), plus cursor visibility and autowrap.
cb.mode = [](void *ctx, structo::hw::vt100_mode m, bool enabled) noexcept { /* ... */ };

// DECSCUSR (CSI n SP q): requested cursor shape, 0..6.
cb.cursor_style = [](void *ctx, std::uint32_t style) noexcept { /* ... */ };

// Bytes the terminal answers with: cursor-position report (CSI 6n), status (CSI 5n) and
// primary device attributes (CSI c). Write them to the application's input, e.g. the pty.
cb.reply = [](void *ctx, reloco::string_view bytes) noexcept { static_cast<pty *>(ctx)->write(bytes); };

// ESC c: a full reset was performed.
cb.reset = [](void *ctx) noexcept { /* ... */ };

term.set_callbacks(cb); // copied; ctx must stay valid while the terminal is fed
```

The mode callback also fires for modes the terminal handles itself
(`cursor_visible`, `autowrap`), and for any other number as
`static_cast<vt100_mode>(n)`.

## Strict VT100 line-feed semantics

`'\n'` moves the cursor down one row (scrolling if already on the last
row) and **does not** also reset the column -- unlike
[`console_ref::put()`](console_ref.md)'s friendlier convenience
interpretation of `'\n'` as CR+LF. Pair it with an explicit `'\r'` for a
conventional newline, exactly as real line-oriented terminal input does
(`"\r\n"`, not just `"\n"`).

## Color mapping

The ANSI color index to `console_color` mapping follows the
conventional Linux-console/most-terminal-emulators assignment:

| ANSI index | Standard intensity | Bright (bold / `9x`/`10x`) |
|---|---|---|
| 0 | `black` | `dark_gray` |
| 1 | `red` | `light_red` |
| 2 | `green` | `light_green` |
| 3 | `brown` (ANSI "yellow") | `yellow` |
| 4 | `blue` | `light_blue` |
| 5 | `magenta` | `light_magenta` |
| 6 | `cyan` | `light_cyan` |
| 7 | `light_gray` (ANSI "white") | `white` |

## API

| Member | Behavior |
|---|---|
| `vt100_terminal()` | Unbound (drives a default-constructed, unbound `console_ref`). |
| `explicit vt100_terminal(console_ref)` | Owns a copy of the given `console_ref` (a lightweight handle; copying it is cheap). |
| `console()` | The underlying `console_ref` this terminal drives (mutable/const overloads). |
| `feed(char)` / `feed(string_view)` | Feeds one byte, or every byte of a string, through the escape-sequence state machine. |
| `set_callbacks(vt100_callbacks)` | Installs the optional event hooks described above. |
| `set_alternate_screen_storage(span<console_cell>)` | Provides `columns*rows` cells enabling the alternate screen. |
| `application_cursor_keys()` / `application_keypad()` / `bracketed_paste()` / `alternate_screen()` | Current mode state; the keyboard side (`console_uart`) uses the first to pick `ESC O x` vs `ESC [ x`. |
| `mouse_tracking()` / `mouse_sgr()` | Mouse-reporting level (`?9`/`?1000`/`?1002`/`?1003`) and SGR encoding (`?1006`) the program requested; `console_uart` generates the reports. |
| `as_sink()` | A `reloco::sink` that feeds everything written to it through `feed()`. |
