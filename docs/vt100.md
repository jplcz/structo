# `structo::hw::vt100_terminal`

`include/structo/hw/vt100.hpp`

A small VT100/ANSI escape-sequence interpreter built entirely on top of
[`console_ref`](console_ref.md), turning a byte stream into console
operations -- usable with any bound backend
([`vga_text_console`](vga_text_console.md),
[`framebuffer_console<PixelFormat>`](framebuffer_console.md), or a test
fake) since it only ever talks to the `console_ref` abstraction.

```cpp
structo::hw::console_ref console(backend); // any adapted backend
structo::hw::vt100_terminal term(console);

term.feed("\x1b[2J\x1b[H");             // clear screen, home cursor
term.feed("\x1b[1;32mHello, green!\x1b[0m\r\n");
```

## Scope

This is a deliberately focused *subset* of VT100/ANSI/ECMA-48, not a
full xterm clone:

- **Cursor movement:** `CUU`/`CUD`/`CUF`/`CUB` (`ESC [ n A/B/C/D`) and
  absolute positioning `CUP`/`HVP` (`ESC [ row ; col H` or `f`,
  1-based, default `1;1`).
- **Erasing:** `ED` (`ESC [ n J`, erase display) and `EL`
  (`ESC [ n K`, erase line), `n` in `{0 = to-end, 1 = from-start,
  2 = all}` (default `0`).
- **`SGR`** (`ESC [ n (; n)* m`): the 16-color set via `30-37`/`40-47`
  (standard intensity) and `90-97`/`100-107` (bright/high intensity),
  `1` (bold -- brightens the *foreground* of a subsequently-set
  standard-intensity color), `22` (normal intensity), `39`/`49`
  (default fg/bg), and `0` (full reset).
- **Raw control characters** outside any escape sequence: `\r` (CR),
  `\n` (LF -- **strict VT100 semantics**, see below), `\b` (BS, one
  column left), `\t` (TAB, next multiple-of-8 column).
- Any other/unrecognized escape sequence is fully consumed (parsed
  through its intermediate bytes to its final byte, per ECMA-48's
  `ESC [intermediate bytes]* final-byte` structure) and silently
  ignored, rather than leaking raw escape bytes onto the screen.

An omitted or explicit-`0` numeric parameter is treated as the
command's default (ECMA-48 convention), e.g. `ESC [ A` and `ESC [ 0 A`
both move the cursor up exactly one row.

## Strict VT100 line-feed semantics

`'\n'` moves the cursor down one row (scrolling if already on the last
row) and **does not** also reset the column -- unlike
[`console_ref::put()`](console_ref.md)'s friendlier convenience
interpretation of `'\n'` as CR+LF. Pair it with an explicit `'\r'` for a
conventional newline, exactly as real line-oriented terminal input does
(`"\r\n"`, not just `"\n"`).

## Color mapping

The ANSI color index to `console_color` mapping follows the
conventional Linux-console/most-terminal-emulators assignment:

| ANSI index | Standard intensity | Bright (bold / `9x`/`10x`) |
|---|---|---|
| 0 | `black` | `dark_gray` |
| 1 | `red` | `light_red` |
| 2 | `green` | `light_green` |
| 3 | `brown` (ANSI "yellow") | `yellow` |
| 4 | `blue` | `light_blue` |
| 5 | `magenta` | `light_magenta` |
| 6 | `cyan` | `light_cyan` |
| 7 | `light_gray` (ANSI "white") | `white` |

## API

| Member | Behavior |
|---|---|
| `vt100_terminal()` | Unbound (drives a default-constructed, unbound `console_ref`). |
| `explicit vt100_terminal(console_ref)` | Owns a copy of the given `console_ref` (a lightweight handle; copying it is cheap). |
| `console()` | The underlying `console_ref` this terminal drives (mutable/const overloads). |
| `feed(char)` / `feed(string_view)` | Feeds one byte, or every byte of a string, through the escape-sequence state machine. |
